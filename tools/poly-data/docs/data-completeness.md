# Data Completeness Manifests (“Complete Enough”)

Day-partitioned orderbook streams can have missing markets, missing outcomes, or large quote gaps.
Those failures can silently bias research/backtests. This repo uses **manifest-driven gating**: for a
given date, compute which tickers are “complete enough”, write an allowlist/exclusion manifest, and
only run downstream jobs on that subset.

## At a glance

- Input: updates-applied **synthetic BBO** parquet (use level-0 bid/ask)
- Optional input (if `spot.enabled=true`): **spot prices** parquet for the configured symbol
- Output: `allowlist.csv`, `exclusions.csv`, `summary.json` under `outputs.out_dir_template`
- Scope: completeness is evaluated per **(date, ticker)**, with outcomes gated together
- Source of truth: `configs/data_completeness.yaml`

## Usage

Build manifests for a given partition date:

- `uv run poly-data completeness --date 2026-01-14`

Common overrides:

- `uv run poly-data completeness --date 2026-01-14 --config configs/data_completeness.yaml`
- `uv run poly-data completeness --date 2026-01-14 --data-root /path/to/data-root`
- `uv run poly-data completeness --date 2026-01-14 --synthetic-bbo ./output/synthetic_bbo_2026-01-14.parquet`
- `uv run poly-data completeness --date 2026-01-14 --out-dir ./output/data_completeness/date=2026-01-14`

Outputs (filenames configurable via `configs/data_completeness.yaml`):

- `allowlist.csv`: per-`(date, ticker)` rows that passed gating (includes required-outcome stats)
- `exclusions.csv`: per-`(date, ticker)` rows that failed gating with a `reason`
- `summary.json`: counts + basic distributions for quick inspection

## Config

The gating spec is encoded in `configs/data_completeness.yaml`:

- **Inputs**: `inputs.data_root` plus path templates (or set `inputs.synthetic_bbo_path` /
  `inputs.spot_prices_path` explicitly).
- **Universe**: `universe.ticker_regexes` and `universe.required_outcomes`.
- **Event-time**: `event_time.horizons_s`, `event_time.max_gap_ms`,
  `event_time.require_forward_freshness_for_max_horizon`.
- **Thresholds**: `thresholds.min_usable_ratio`, `thresholds.min_usable_events`,
  `thresholds.max_end_gap_ms`, `thresholds.max_inter_event_gap_ms`.
- **Spot**: `spot.enabled`, `spot.symbol`, `spot.max_gap_ms`, `spot.min_usable_ratio`,
  `spot.min_usable_events`.
- **Outputs**: `outputs.out_dir_template` and output filenames.

Key defaults:

- `event_time.horizons_s = [0.5, 1.0, 1.5, 2.0]`
- `event_time.max_gap_ms = 2000`
- `thresholds.min_usable_ratio = 0.98`
- `thresholds.min_usable_events = 1000`
- `thresholds.max_inter_event_gap_ms = 120000`
- `spot.max_gap_ms = 2000`
- `spot.min_usable_ratio = 0.98`
- `spot.min_usable_events = 1000`

## How “complete enough” is computed

Scope: a **single date** and a universe of Polymarket tickers, evaluated on an updates-applied
**synthetic BBO** stream (use level-0 bid/ask).

### Required input

- **Synthetic BBO Parquet** (required): updates-applied snapshots matching live semantics.
  - Generated by `poly-mm-backtest` (see `research/orderbook-data.md`).
  - Must include at least: `ts`, `ticker`, `outcome`, `bid_price_0`, `ask_price_0` (plus any extra columns).

### Optional inputs

- **Spot prices Parquet**: used for gating when `spot.enabled=true` (default). Required for
  downstream feature sets that join external spot prices.
- **Raw snapshots/updates locations**: recorded for audit/debug if you use the config templates.

### Universe + required outcomes

- Universe is selected by regex patterns applied to `ticker` (default matches BTC 15m up/down
  markets: `btc-updown-15m-{unix}`).
- A ticker is only eligible if **all required outcomes** pass gating (default: `Up` and `Down`).

### Event-time gating (no grid)

Completeness is evaluated at **event time** `t` for each snapshot update:

- Use the actual snapshot timestamp as the row index (no fixed grid).
- A row at time `t` is **labelable** if:
  - the current quote is valid (see “Quote validity”), and
  - `t + h_max <= end_date` where `h_max = max(horizons_s)`, and
  - the last quote at or before `t + h_max` is valid and **fresh**:
    `(t + h_max - last_quote_ts) <= max_gap_ms`.
- The evaluation window starts at the market open time when the ticker suffix is a UNIX timestamp
  (e.g., `btc-updown-15m-<open_ts>`); otherwise it starts at the first observed timestamp.
- If the ticker encodes a duration (e.g., `15m`, `1h`), the evaluation window ends at
  `start + duration` (clamped by `end_date` if earlier).
- Rows beyond `effective_end - h_max` are excluded to prevent tail leakage.

### Quote validity

By default, a quote is considered valid when:

- `bid_price_0` and `ask_price_0` are non-null,
- `ask_price_0 - bid_price_0 >= 0`,
- and (optionally) prices are bounded within `[0, 1]` (Polymarket probability prices).

No repair/fabrication is allowed: invalid quotes are simply treated as missing.

### Completeness score + threshold

For each `(date, ticker, outcome)` compute:

- `usable_ratio(outcome)` = fraction of event-time rows that are labelable (fresh at `t` and `t+h_max`).

Define per-ticker score:

- `score(ticker) = min(usable_ratio(Up), usable_ratio(Down))`

Gate rule:

- `complete ⇔ score(ticker) >= min_usable_ratio` (default `0.98`) **and**
- each required outcome has at least `min_usable_events` usable rows (default `1000`), to prevent
  tiny windows from passing on small samples.
- if the last valid quote is too far before market end, exclude the ticker
  (`max_end_gap_ms`, default `300000ms`).
- if any required outcome has `max_inter_event_gap_ms` above the outage threshold,
  exclude the ticker (`max_inter_event_gap_ms`, default `120000ms`).

### Spot coverage (optional)

If `spot.enabled=true`, spot freshness is evaluated **at event times**:

- Filter the spot parquet to `spot.symbol` (e.g., `BTCUSDT`).
- For each event time `t`, use the most recent spot price at or before `t`.
- A spot quote is **fresh** if `(t - spot_ts) <= spot.max_gap_ms`.
- Spot freshness is enforced as part of row-level labelability.

Spot gating rules (per ticker):

- `spot_insufficient_usable_events` if usable event rows `< spot.min_usable_events`.
- `spot_usable_ratio_below_threshold` if usable ratio `< spot.min_usable_ratio`.
- `spot_missing_symbol` if the spot symbol has no rows in the parquet.
- `spot_no_valid_prices` if the symbol has rows but no valid prices (`price > 0`).

If `spot.enabled=true` and the spot parquet is missing, `poly-data completeness` fails fast.
